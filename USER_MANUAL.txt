Trends Service User Manual

Overview
- Standalone NestJS microservice for Trends MongoDB aggregation.
- Frontends call `POST /trends` directly.
- User JWT and service-to-service authentication are not implemented in this step.

Request flow
Frontend -> POST /trends with projectId -> ProjectConfigService -> memory cache -> configuration DB on miss -> project MongoDB -> response.

The client provides only the project identifier and Trends query fields. It cannot select a database or collections.

Environment
- `MONGO_URI` - MongoDB connection URI (required).
- `CONFIG_DB_NAME` - configuration database name (required).
- `CONFIG_ADMIN_TOKEN` - admin token for project/collection CRUD (required).

Configuration CRUD

All configuration endpoints require `Authorization: Bearer <CONFIG_ADMIN_TOKEN>`.

Projects:
- `POST /projects`
- `GET /projects`
- `GET /projects/:projectId`
- `PATCH /projects/:projectId`
- `DELETE /projects/:projectId` (soft delete)

Collections:
- `POST /projects/:projectId/collections`
- `GET /projects/:projectId/collections`
- `PATCH /projects/:projectId/collections/:collectionId`
- `DELETE /projects/:projectId/collections/:collectionId` (soft delete)

Project creation body:

```json
{"projectId":"ems","name":"EMS","databaseName":"ems_db","nodeRedUrls":["http://localhost:1880"],"isActive":true}
```

Collection creation body:

```json
{"collectionName":"historical_z1","isActive":true}
```

Projects and collections are stored in the configuration DB. The Trends service caches resolved projects in memory for 60 seconds. Mutations invalidate the affected project cache. Adding or changing configuration does not require a TypeScript change.

Example request

```json
{
  "projectId": "ems",
  "start_date": "2026-06-01",
  "end_date": "2026-06-01",
  "start_time": "00:00:00",
  "end_time": "23:59:59",
  "meterIds": ["PG_PC_Z4_GW0_PLC2_EM11"],
  "suffixes": ["AMP_AVG", "CURR_L2"],
  "userTimezone": "Asia/Karachi"
}
```

`POST /trends` returns the existing `{ timezone, data }` response structure. `projectId`, dates, times, meter IDs, and suffixes are required. Times use `HH:mm:ss`. `userTimezone` is optional and defaults to `Asia/Karachi`.

MongoDB behavior

NestJS `MongooseModule.forRootAsync()` owns the single MongoDB connection. The service selects a configured project database using Mongoose's cached `useDb` mechanism and queries only that project's configured collections. It does not create a connection per request.

Development
